\heading{The problem}

In anti-money-laundering screening, credit-risk assessment and banking supervision
an answer is useful only if it can be traced back to a source record. A language
model asked directly does not meet that bar: ask a general-purpose chat assistant
which entities Siemens consolidates and it returns about a dozen plausible names,
none of them carrying the identifier you would need to check it. Ask the register
and you get exactly \textbf{452} entities that report Siemens Aktiengesellschaft as
their direct consolidation parent, each one traceable to its record by LEI.

\vspace{2mm}
\takeaway{So do not trust the answer. Trust the query, and read it.}

\heading{The register}

GLEIF publishes the Legal Entity Identifier register as CC0 open data with an
official RDF ontology --- a real regulatory source rather than an encyclopaedic or
synthetic graph. We pin one 8-hourly publish and query it locally.

\vspace{1mm}
\panel{%
\BodyF
\begin{tabular}{@{}l@{\hspace{8mm}}r@{}}
Level 1 entity records         & 3{,}382{,}301 \\
\quad of which \textsc{issued} & 1{,}940{,}941 \\
Level 2 relationships          & 481{,}557 \\
Triples in the store           & 69.7\,M \\
Populated predicates           & 27 \\
Guard vocabulary               & 71 terms \\
Snapshot                       & \texttt{20260723-1600} \\
\end{tabular}
\par\vspace{4mm}
{\SmallF\textcolor{muted}{The 71-term guard vocabulary is everything a query may
name: all 27 populated predicates, plus the 44 classes and enumerated code values
they take. Every term is count-backed --- it is in the prompt because it is in the
graph.}}}

\heading{The system}

A local open-weight model (\texttt{gpt-oss-20b}, served through LM Studio at
temperature 0, prompting only, no training) turns the question into candidate
SPARQL. A guard checks the query \emph{before} it runs; a bounded repair loop of at
most two retries feeds the guard's diagnostic back to the model. The query, its
rows and the LEIs behind them are returned with every answer.

\vspace{3mm}
\includegraphics[width=\linewidth]{../blog/pipeline.pdf}

\vspace{2mm}
{\SmallF\textcolor{muted}{One shot, not agentic search: the guard, and not iterative
graph exploration, is what keeps the output valid. The loop never retries on an
empty result --- for a question the register cannot answer, empty is the right
answer.}}

\heading{Cost}

Queries return in well under a second, except full-population aggregates at 14--28
seconds. Latency is dominated by generation (15--40 seconds), not by the store. The
whole system runs on one machine and makes no external call, so the data never
leaves the premises.

\heading{One question, end to end}

A held-out item (\texttt{h55}), exactly as the system logged it. This is the whole
audit trail an analyst sees.

\vspace{1mm}
\stage{Question}{business language, names no predicate}
\codepanel[tealsoft]{What is the legal form name of the direct\\
consolidation parent of 'AMERICAN AXLE \&\\
MANUFACTURING, INC.'?}

\vspace{-4mm}
\stage{Attempt 1}{model output --- rejected by the guard}
\codepanel{SELECT ?parentFormLabel WHERE \{\\
\ \ ?child a gleif-L1:RegisteredEntity ;\\
\ \ \ \ \ \ \ \ \ gleif-L1:hasLegalName\\
\ \ \ \ \ \ \ \ \ \ \ "AMERICAN AXLE \& MANUFACTURING, INC." .\\
\ \ ?child kgx:hasDirectConsolidationParent ?parent .\\
\ \ \textcolor{warm}{?parent gleif-base:hasLegalForm ?form .}\\
\ \ ?form rdfs:label ?parentFormLabel .\\
\}}

\vspace{-4mm}
\panel[warmsoft]{\SmallF\textbf{\textcolor{warm}{Guard:}} unknown vocabulary
\texttt{gleif-base:hasLegalForm} --- the predicate does not exist in the graph.

\vspace{-4mm}
\stage{Attempt 2}{repaired --- passes the guard, executes}
\codepanel{PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema\#>\\

\ \ ?child a gleif-L1:RegisteredEntity ;\\
\ \ \ \ \ \ \ \ \ gleif-L1:hasLegalName\\
\ \ \ \ \ \ \ \ \ \ \ "AMERICAN AXLE \& MANUFACTURING, INC." .\\
\ \ ?child kgx:hasDirectConsolidationParent ?parent .\\
\ \ \textcolor{teal}{?parent gleif-L1:hasLegalForm ?form .}\\
\ \ ?form rdfs:label ?parentFormLabel .\\

\vspace{-4mm}
\stage{Answer, with the records behind it}{}

"Corporation"\\[7mm]
\textcolor{muted}{child\ \ lei:RY5TAKFOBLDUGX31MS24\\
parent lei:254900SMQY98VFKNCC32\\
form\ \ \ elf:XTIQ\ \ (ISO 20275)}}

\heading{What the guard does not do}

The guard is an existence check, not a semantic one. It guarantees that the query
parses and that every term it names is in the graph, which is what stops a
hallucinated predicate from ever reaching the store. It does \textbf{not} guarantee
that the query means what the question asked.

\vspace{2mm}
\takeaway{That boundary is the design and not a gap in it: a wrong answer arrives
as a readable query returning wrong rows, never as fluent prose.}

\heading{Where the errors are not}

All twelve held-out errors are queries that ran and returned the wrong rows. None
is invalid, none names a predicate that does not exist, and the model declines
every out-of-scope and absent-entity question it is given.

\heading{Benchmark}

144 questions over six tiers, written from a specification fixed \emph{before}
instantiation around a KYC analyst, a supervisor and a fund-operations user, in
business language naming no predicate or IRI. Every reference query is executed
against the pinned snapshot, so its result --- the gold answer --- cannot drift
from the graph. The 54-question development set drove three schema revisions; the
90-question held-out set was written afterwards against a frozen prompt and
informed none.

\heading{Limits, and what is next}

144 questions on one graph with a thin schema, one snapshot, one machine, one run
per model, and no user study yet. The construction, however, is not specific to
corporate structure: it is a model writing queries against any source described by
an ontology. Real data sits across relational stores, graph stores, document stores
and PDFs, each with its own query language --- extending the same
generate--guard--repair loop across them, routing each question to the store that
can answer it and keeping every answer decomposable into a checkable query, is the
direction we intend to pursue.
